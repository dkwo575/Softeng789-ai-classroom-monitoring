# Phase 3A — 웹캠 얼굴·머리 움직임 로컬 테스트

## 이번에 구현한 범위

학생 포털에서 본인이 웹캠을 켜고 얼굴 유무·여러 얼굴·머리 방향 변화를 확인하는 **3A 로컬 테스트**입니다. MediaPipe Face Landmarker를 브라우저의 별도 작업 스레드에서 실행합니다. Python 얼굴 인식 서버나 얼굴 등록 데이터는 사용하지 않으므로 수동 출석 학생도 테스트할 수 있습니다.

영상·음성·관찰 이벤트를 서버에 보내거나 파일로 저장하지 않습니다. 교사는 아직 이 결과를 볼 수 없으며 기존 Live monitoring은 모의 화면 그대로입니다. 실제 교사 화면과 이벤트 전송은 3B 범위입니다. 사진 출석과 관리자 가입 승인은 기존대로 유지합니다.

## 설치와 실행

현재 개발 PC에는 모델을 설치했습니다. 다른 PC 또는 새 체크아웃에서는 다음을 실행합니다.

```powershell
npm --prefix frontend ci
npm --prefix frontend run setup:webcam
```

설치 스크립트는 버전 1 모델의 SHA-256을 확인하고 MediaPipe 1.1.1 실행 파일·WASM·라이선스를 `frontend/public/webcam-model/`에 준비합니다. 이 폴더는 Git 제외 대상입니다. 배포용 빌드 전에도 이 설치가 필요합니다. 사용자 브라우저에서는 외부 CDN이 아닌 웹 앱과 같은 주소에서 파일을 받습니다.

현재 PC의 서버 실행·종료 명령은 그대로입니다. DB 초기화나 마이그레이션은 필요하지 않습니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\data\local-dev\start.ps1
powershell -ExecutionPolicy Bypass -File .\data\local-dev\stop.ps1
```

## 직접 테스트 순서

1. 승인된 **학생 계정**으로 로그인 후 Overview/Home을 엽니다. 모바일도 Home에 있습니다.
2. 기존 사진 출석 영역 아래의 **Open webcam movement test**를 누릅니다.
3. 성인 자원 테스트 및 로컬 분석 동의 체크박스를 체크합니다. 열기만 해서는 카메라가 켜지지 않습니다.
4. **Start camera test**를 누르고 카메라 권한을 허용합니다. 첫 모델 로딩에는 시간이 걸릴 수 있습니다.
5. 얼굴을 정면으로 두고 한 얼굴 감지를 확인한 뒤 **Set forward reference**를 누릅니다. 현재 자세를 기준으로 삼습니다.
6. 고개를 천천히 돌리거나 기울여 2초 이상 유지합니다. 기준 대비 방향 변화와 로컬 이벤트를 확인합니다. 정면 기준이 부정확하면 다시 설정합니다.
7. 화면에서 얼굴을 10초 넘게 빼면 **No face detected** 이벤트가 생깁니다. 잠깐 고개를 숙이거나 카메라를 가리는 것만으로 바로 이벤트를 만들지 않습니다.
8. 추후 동의한 다른 사람과 두 얼굴을 2초 이상 보여 **Two or more faces detected**를 확인합니다. 최대 두 얼굴을 감지하는 설정이며 인원수 측정이나 신원 인식이 아닙니다.
9. **Stop camera test**로 중지합니다. 동의를 취소하거나 테스트를 닫거나 다른 화면으로 이동해도 카메라가 꺼집니다. 다른 탭으로 가면 자동 중지되며 돌아와서 직접 시작해야 합니다.

**Clear observations**는 화면의 기록만 비웁니다. 중지는 기록을 잠시 남기고, 새로 시작·테스트 닫기·화면 이동·동의 철회는 기록을 비웁니다. 최대 50개만 브라우저 메모리에 보관합니다. 기준 자세도 중지하면 초기화됩니다.

Chrome 개발자 도구에서 390px 화면으로 테스트할 수 있습니다. 실제 휴대폰·Safari 및 배포 환경은 별도 테스트가 필요합니다. 카메라는 localhost 또는 신뢰된 HTTPS에서 사용합니다.

## 결과를 해석할 때

- **No face detected**는 모델이 얼굴을 못 찾았다는 뜻입니다. 결석이나 교실 이탈 판정이 아닙니다.
- 머리 방향은 기준 대비 yaw 20도 또는 pitch/roll 15도 이상의 변화를 시험하는 값입니다. 집중도·졸음·감정·시선 판정이 아닙니다.
- 정면 기준은 사용자가 직접 잡습니다. 자동 자세 검증이나 실제 사람이 지금 있는지 확인하는 기능은 없습니다.
- 카메라 오류·끊김·분석 지연은 얼굴 미검출과 구분합니다. 분석 결과 사이에 1.5초 넘는 공백이 있으면 지속 시간을 다시 계산합니다.
- 최대 약 5회/초로 분석하며 한 번에 한 프레임만 처리합니다. 저사양 기기에서는 더 느릴 수 있습니다.
- 공개 모델 문서는 가까운 정면 얼굴·AR 용도를 설명하며 감시/신원 인식은 용도 밖이라고 명시합니다. 3A는 자발적인 로컬 실험이며 교사에게 전송하는 3B는 모델 적합성·동의·개인정보·배포 지역 검토가 따로 필요합니다.

## 오류가 나오면

- 모델 로드 실패: `npm --prefix frontend run setup:webcam` 실행 후 새로고침합니다.
- 카메라 권한 거부: 사이트 카메라 권한을 허용하고 다시 시작합니다.
- 카메라 연결 끊김·분석 시간 초과: 원인을 해결한 뒤 다시 시작합니다. 오류 시간을 결석으로 처리하지 않습니다.
- 얼굴이 잘 안 잡힘: 카메라에 가까이, 얼굴 전체가 보이도록, 밝은 곳에서 테스트합니다.

## 검증 결과 — 2026-10-24

- 프론트엔드 테스트 **355개 통과**, TypeScript/Vite 빌드 통과, 변경 파일 공백 검사 통과.
- 실제 MediaPipe 모델로 빈 프레임·한 얼굴·두 얼굴·기준 설정 후 이미지 기울기에 따른 이벤트를 확인했습니다.
- 1280px/390px 화면, 동의 조건, 중지·철회·탭 숨김·컴포넌트 종료 시 카메라 해제를 확인했습니다. 가로 넘침과 페이지 JavaScript 예외가 없었습니다.
- 분석 테스트 중 서버 POST와 외부 추론 요청이 없었습니다. 모델의 CPU 초기화 안내와 임시 테스트 화면의 favicon 404는 기능 오류와 구분했습니다.
- 실제 로컬 학생 로그인으로 데스크톱·모바일 포털 진입과 동의 조건을 확인했습니다. 출석·가입 기록은 변경하지 않았습니다.

실제 모델 자동 테스트는 공개 테스트 이미지로 만든 영상과 빈 프레임을 사용합니다. 실제 여러 사람의 정확도나 집중·수면 상태를 검증한 것이 아닙니다. API·DB 변경과 커밋·푸시·운영 배포는 이번 구현 범위에 없습니다.
