# Phase 3C — 학생 실시간 영상 공유

학생이 직접 공유를 시작하면 교사가 해당 수업의 학생 영상을 보는 기능입니다. **성인 자원자 대상 로컬 파일럿이며 수업당 최대 4명, 학생 한 명당 교사 브라우저 연결 1개**를 지원합니다. 사진 출석은 기존대로 유지하며, 하나의 카메라 화면에서 관찰 이벤트와 실시간 영상을 각각 공유할 수 있습니다. 앱에서 녹화·음성 전송·집중도·수면 판정을 하지 않습니다. 수신자의 별도 화면 녹화까지 막을 수 있는 기능은 아닙니다.

## 실행 및 테스트 순서

1. 기존 로컬 실행 명령을 그대로 사용합니다. 백엔드 설정에 `LIVE_VIDEO_ENABLED=true`가 필요합니다. 로컬 실행기는 `data/local-dev/settings.json`을 읽으며 설정 변경 후 백엔드를 재시작합니다. 기본값은 꺼짐이고, 3C 때문에 DB를 초기화하거나 마이그레이션할 필요는 없습니다.
2. **학생과 교사는 서로 다른 브라우저 프로필 또는 시크릿 창**으로 로그인하세요. 일반 탭끼리는 로그인 쿠키를 공유합니다. 학생은 관리자 승인과 수강 등록이 완료되어 있어야 합니다. 수업 시작 15분 전부터 종료 전까지 공유할 수 있습니다.
3. 학생 Overview에서 **Open classroom camera** → **Class session for sharing** 선택 → 성인 참여·로컬 분석 동의 → **Start camera** 순으로 진행합니다. 카메라와 미리보기는 하나이고, 공유 스위치는 처음에 모두 꺼져 있습니다.
4. **Share observation events**는 관찰 결과만 공유하고, **Share live video**는 영상을 공유합니다. 두 스위치는 독립적으로 켜고 끌 수 있습니다. 수업을 선택하지 않으면 로컬 분석만 가능합니다. 수업을 바꾸려면 먼저 카메라를 중지하세요.
5. 교사는 **Live monitoring** → 같은 수업 선택 → **Start viewing live video**로 영상을 봅니다. **Enlarge / Reduce**로 확대·축소합니다. 학생 화면에는 접속한 교사의 이름이 표시됩니다.
6. 영상 공유를 꺼도 로컬 분석과 이벤트 공유는 유지됩니다. 이벤트 공유를 꺼도 영상은 유지됩니다. **Withdraw and delete shared observations**는 관찰 기록만 삭제하며 영상은 중단하지 않습니다.
7. **Stop camera**, 성인·로컬 분석 동의 해제, 패널 닫기 또는 페이지 이동은 카메라와 두 공유를 모두 중단합니다. 카메라를 다시 켜도 공유는 자동으로 시작되지 않습니다.
8. 영상 또는 이벤트 통신 오류는 해당 공유만 중단합니다. 복구 후 해당 스위치를 직접 켜세요. 카메라·로컬 분석 모델 오류는 전체를 중단합니다. 현재 통합 카메라는 로컬 분석 동의가 필요합니다. 교사의 **Stop viewing live video**는 교사 수신만 중단하며 끊김을 결석·불집중으로 판단하지 않습니다.

## 범위와 제약

- 브라우저 WebRTC를 사용하며 새 AI 모델은 필요하지 않습니다. 기본 목표는 640×480, 15fps 영상입니다. 서버는 짧은 연결 정보만 메모리에 보관하고 영상 파일은 저장하지 않습니다.
- 연결 정보 유효 시간은 20초이며 만료 정보는 주기적으로 제거합니다. 클라이언트는 통신 확인이 15초 이상 끊기면 실행 가능한 시점에 영상 전송용 트랙·연결을 닫고 로컬 카메라와 이벤트 공유는 유지합니다. OS가 브라우저 전체를 멈추면 브라우저가 재개되기 전까지 코드가 실행되지 않을 수 있습니다.
- 현재 외부 STUN/TURN 중계는 사용하지 않아 localhost 또는 호환되는 로컬 네트워크에서 먼저 테스트합니다. 다른 인터넷망·학교 방화벽·실제 휴대폰 환경의 연결은 보장되지 않습니다. WebRTC 직접 연결은 상대방에게 네트워크 주소가 노출될 수 있어 동의 안내에 포함했습니다.
- 학생 20명 이상 및 인터넷 배포는 **TURN 중계·SFU 영상 서버 검토와 별도 부하 테스트**가 필요합니다. 이번 서버 메모리 방식은 백엔드 한 대의 파일럿용입니다.
- 테스트용 모의 카메라·브라우저 검증은 실제 학생 여러 명과 휴대폰의 정확도·성능 검증을 대신하지 않습니다. 계정 표시 이름은 영상 속 사람이 해당 학생이라는 신원 인증 결과가 아닙니다.

API·구조·테스트 범위는 [영문 구현 가이드](phase3c-live-video.md)를 참고하세요.

## 이번 검증 결과

2026-10-26 기준 프론트엔드 371개 테스트·빌드, 영상 백엔드 11개와 기존 관찰·아키텍처 21개 테스트를 통과했습니다. 임시 학생 계정 2개와 교사 계정 사이에서 **실제 WebRTC 연결**을 사용해 수신 프레임·송신 바이트·음성 없음·확대·교사 중지 후 재접속·학생 동의 철회·통신 실패 시 카메라 종료를 확인했습니다. 연결 정리와 재접속이 겹치는 문제를 발견해 이전 해제가 끝난 뒤 재접속하도록 수정했습니다. 모의 카메라 영상으로 검증했으며, 실제 얼굴·별도 기기·외부 인터넷망·20명 동시 접속을 검증한 것은 아닙니다. 모바일 너비 390px 배치도 확인했습니다. 임시 계정과 수업은 정리했고 기존 출석 데이터는 변경하지 않았습니다.

## 카메라 통합 변경

학생 화면의 두 진입 버튼을 **Open classroom camera** 하나로 통합했습니다. 별도 웹캠을 다시 요청하지 않고 같은 영상의 트랙을 복제하여 전송하므로, 영상 공유 종료가 로컬 분석을 중단하지 않습니다. 백엔드 API·DB·권한·출석 흐름은 변경하지 않았으며 추가 마이그레이션이 필요하지 않습니다. 기존 서버 시작·종료 명령도 그대로 사용합니다.

통합 검증: **프론트엔드 376개 테스트 및 빌드 통과**. 로컬 실제 API·DB·MediaPipe 모델·WebRTC와 모의 카메라를 사용하여 카메라 요청 1회, 이벤트·영상 동시 공유, 각각의 공유 중지 및 통신 오류, 관찰 삭제 중 영상 유지, 전체 종료, 재시작 후 공유 OFF, 늦은 시작 응답 취소, 빠른 ON/OFF, 동의 철회, 카메라 권한 거부·재시도, 패널 종료를 검증했습니다. 모바일 너비 390px에서 가로 넘침과 페이지 오류가 없었습니다. 임시 계정·수업은 삭제했으며 출석 기록을 생성하지 않았습니다. 통합 변경은 프론트엔드에 한정되므로 백엔드 테스트는 위 기존 검증 결과를 유지하고 이번에 다시 실행하지 않았습니다. 실제 휴대폰·다른 네트워크·20명 동시 접속 검증은 아직 필요합니다.
