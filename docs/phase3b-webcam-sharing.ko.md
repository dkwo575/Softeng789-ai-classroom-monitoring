# Phase 3B 구현 및 테스트 가이드

3A가 학생 기기 안에서 얼굴의 보임 여부와 머리 방향 변화를 확인했다면, 3B는 **학생이 별도로 동의한 경우에만 그 이벤트를 담당 교사에게 전달하고 검토**하는 단계입니다. 수면·집중도·감정은 판단하지 않고, 사진/수동 출석도 변경하지 않습니다.

## 이번에 추가한 기능

| 학생 화면 | 교사 화면 |
| --- | --- |
| 수강 중인 수업 선택, 성인 자원 참여 확인, 별도 공유 동의 | Live monitoring에서 실제 공유 연결 상태 확인 |
| 이벤트 종류·지속 시간만 공유, 영상은 기기 안에서 처리 | 학생 이름 검색, 여러 학생의 연결 상태를 간결한 카드로 확인 |
| 정지 및 공유 철회/기록 삭제 | 학생별 요약, 선택적 확인 목록과 묶음 검토 |

공유를 선택하지 않으면 3A처럼 로컬 테스트만 됩니다. 공유를 해도 사진·영상·음성·랜드마크·머리 각도 값은 서버로 전송하지 않습니다. 서버에는 계정/수업, 동의 버전, 연결 상태, 이벤트 종류·지속 시간·서버 수신 시각, 검토 결과만 남습니다. 로그인한 계정으로 전송되지만 카메라 앞 사람이 그 학생이라는 보장은 없습니다.

## 실행

기존 명령어를 그대로 사용합니다. 저장소 루트 PowerShell에서:

```powershell
# 종료 (실행 중인 서버에 새 코드/설정을 반영할 때 먼저 실행)
powershell -ExecutionPolicy Bypass -File .\data\local-dev\stop.ps1

# 시작
powershell -ExecutionPolicy Bypass -File .\data\local-dev\start.ps1
```

주소는 `http://127.0.0.1:5173`입니다. 시작 명령만 다시 실행하면 이미 실행 중인 백엔드는 재시작되지 않습니다.

공유 기능은 기본값이 꺼짐입니다. 로컬 실행기의 `data/local-dev/settings.json`에서 `WEBCAM_SHARING_ENABLED`를 `true`로 설정하고 백엔드를 재시작하면 활성화됩니다. 이 파일에는 비밀 설정이 있으므로 Git에 올리지 않습니다. `.env.example` 변경만으로 로컬 실행기 설정이 바뀌지는 않습니다.

3A 모델 파일이 없다면 `frontend`에서 `npm run setup:webcam`을 한 번 실행합니다. 새로운 Python 환경이나 YOLO 설치는 필요 없습니다. 기존 MediaPipe Face Landmarker를 브라우저 CPU worker에서 그대로 사용합니다.

기존 Flyway V6 DB에는 시작 시 V7·V8 마이그레이션이 자동 적용됩니다(V7 DB는 V8만 적용). 웹캠 공유용 테이블 2개와 보완된 상태가 추가되고 기존 계정·얼굴·출석 데이터는 유지됩니다. DB를 초기화하거나 예전 `database/schema.sql`을 실행하지 마세요.

## 직접 테스트하는 순서

1. **교사:** 테스트 학생이 등록된 수업을 현재 시각에 맞게 예약합니다. 공유 가능 시간은 수업 시작 15분 전부터 종료 전까지입니다.
2. **학생:** 로그인 → Overview → Open webcam movement test를 누릅니다. 계정은 관리자 승인 및 활성 상태여야 합니다.
3. 성인 자원 참여와 로컬 분석 동의를 체크합니다. 수업을 선택하고 별도의 이벤트 공유 동의도 체크한 뒤 **Start camera and share events**를 누릅니다.
4. **다른 브라우저/프로필의 교사:** Live monitoring에서 같은 수업을 선택합니다. Camera starting → Camera connected 상태와 학생 목록을 확인합니다.
5. **학생:** 정면을 보고 Set forward reference를 누릅니다. 고개를 천천히 돌리거나 기울여 2초 이상 유지하고, 얼굴을 화면 밖으로 10초 이상 이동해 봅니다.
6. **교사:** 전송과 갱신에 추가로 약 5–10초를 기다립니다. 해당 이벤트에서 Mark group reviewed 또는 Group is false positive를 선택합니다. 기존 출석 상태가 바뀌지 않는지 확인합니다.
7. 학생이 Stop camera test를 누르면 Camera off가 됩니다. 창을 전환하거나 최소화해도 카메라를 의도적으로 끄지 않습니다. 패널을 닫거나 페이지를 떠나면 카메라가 멈춥니다. 통신이 갑자기 끊기면 마지막 신호로부터 35초 뒤 Connection lost가 되며, 이를 얼굴 없음이나 결석으로 기록하지 않습니다.
8. 학생이 **Withdraw and delete shared observations**를 누르면 그 학생의 보관 중인 모든 수업 공유 기록과 검토 기록이 삭제됩니다. 기존 얼굴 등록이나 출석은 삭제하지 않습니다. 삭제 확인에 실패하면 안내를 보고 다시 시도할 수 있습니다.

공유 중에는 다른 수업으로 바꿀 수 없습니다. 정지 후 다시 선택하세요. 다른 탭에서 새 공유를 시작하면 이전 공유는 종료되며, 통신 오류 뒤에는 이벤트 공유가 중단되지만 이미 실행 중인 로컬 카메라는 유지됩니다. Reconnect event sharing으로 명시적으로 다시 연결하며, 쌓인 이벤트를 재전송하지 않습니다.

## 상태와 기록을 읽는 방법

- **Camera connected:** 분석 결과를 처리하는 브라우저가 최근 연결 신호를 보냈습니다. 얼굴이 보인다는 뜻은 아닙니다.
- **No face detected:** 연속으로 10초 동안 얼굴 검출이 되지 않았다는 클라이언트 보고입니다. 자리를 떠났다는 증거는 아닙니다.
- **Camera off / Connection lost:** 명시적 정지 / 신호 만료입니다. 결석이나 수면 판정이 아닙니다.
- **Updates stale:** 교사 화면 갱신이 실패하거나 오래됐습니다. 마지막 데이터를 실시간 상태로 판단하지 않도록 검토 버튼이 비활성화됩니다.
- 표시된 지속 시간은 이벤트를 처음 내보내기 전의 연속 관찰 구간입니다. 이후 행동이 얼마나 오래 계속됐는지 나타내지 않습니다. Received는 서버 수신 시각입니다.
- Reviewed는 교사의 확인 표시이며, 학생 행동이 사실이라고 확정하거나 성적·출석에 반영하지 않습니다.

기록은 공유 시작 후 24시간이 지나면 조회할 수 없고, 실행 중인 서버에서 최대 10분 뒤 정리됩니다. 정지는 기록을 바로 지우지 않으므로 즉시 삭제하려면 철회를 사용합니다. 서버가 꺼져 있으면 재시작 후 정리되며, 별도 DB 백업의 보존 기간은 따로 관리해야 합니다.

## 범위와 남은 확인

성인 자원 참여용 로컬 파일럿입니다. 실제 기관 배포 전에는 적용 법규, 기관 정책, 자발적 동의, MediaPipe 모델 카드의 감시 용도 제한과 적합성, 보안 및 백업 보존 정책을 검토해야 합니다. 성인 동의만으로 모든 이용이 허용되는 것은 아닙니다. 이번 구현은 수면·피로·집중도·감정 추론의 적법성을 주장하지 않습니다.

실제 휴대폰 카메라/HTTPS, 여러 사람과 다양한 조명에서의 정확도, 동시 접속 부하 검증은 추가 단계입니다. 세부 API·DB·구조는 [영문 구현 가이드](phase3b-webcam-sharing.md)를 참고하세요.

## 3B 보완 사항 및 추가 테스트

V8 마이그레이션이 분석 일시 중단(PAUSED)과 참고 기록(INFO)을 추가합니다. 기존 V7은 변경하지 않습니다. 기존 기록 중 아직 검토하지 않은 정상 얼굴·고개 움직임 기록은 INFO로 바뀌며, 이미 저장된 교사 검토 결과는 유지됩니다.

2026-10-25 검증: 프론트엔드 367개 테스트·빌드, 관련 백엔드 52개 테스트, PostgreSQL 신규 DB/V6 업그레이드 검증을 통과했습니다. 실제 로컬 API/DB에 연결한 Chrome에서 탭 전환, 숨김 상태·영상 정지 모의, 분석 중단·재개, 보고 2개 묶음 검토, 상세 이력, 공유 실패·재연결, 중지·철회를 확인했습니다. 데스크톱·모바일 너비도 확인했습니다. 합성 카메라 영상을 사용했으므로 실제 OS 최소화·휴대폰 중단 동작과 여러 사람 인식 정확도는 기기에서 별도로 테스트해야 합니다.

1. 학생이 공유를 켠 상태에서 코딩 창으로 전환하거나 브라우저를 최소화해 보세요. 카메라를 의도적으로 끄지 않습니다. 브라우저가 분석을 제한하면 **Analysis temporarily unavailable**로 표시하고, 그 시간을 얼굴 미검출이나 집중 부족으로 계산하지 않습니다.
2. 창으로 돌아와 새 영상 프레임을 받으면 분석이 재개됩니다. 장시간 브라우저 정지로 공유 연결이 만료됐다면 **Reconnect event sharing**을 누르세요. 끊기기 전 이벤트는 나중에 몰아서 전송하지 않습니다. 실제 모바일 백그라운드 동작은 기기별 검증이 필요합니다.
3. 교사 화면은 **학생 한 명당 한 줄인 표**로 이름·연결 상태·선택적 확인 건수를 보여줍니다. 상단 **All students / Connected / Analysis paused / With optional checks**를 눌러 필터링하고 이름으로 검색할 수 있습니다. 이름순으로 20명씩 표시하며 **Previous students / Next students**로 이동합니다. `+`를 누르면 한 학생의 고개 움직임·얼굴 미검출·복수 얼굴 횟수와 마지막 연결 시각이 펼쳐집니다. 수치는 해당 수업의 보관 중인 전체 보고를 집계하며 집중도 점수가 아닙니다.
4. **Review reports and detailed history**를 펼치면 **Optional checks**에서 얼굴 미검출(연속 10초)과 복수 얼굴(연속 2초)을 확인합니다. 정상 얼굴·복귀·고개 움직임은 **Show detailed history**에서 볼 수 있고 교사 확인이 필요하지 않습니다. 상태 필터·20명 페이지는 학생 표에만 적용하고, 이름 검색은 보고 목록에도 적용합니다. 보고는 별도로 50개씩 조회합니다. 임계값 설정 UI는 이번 범위에 포함하지 않았습니다.
5. 같은 학생·유형의 반복 보고를 현재 페이지 안에서 묶습니다. **Mark group reviewed / Group is false positive**를 누르면 그 묶음에 표시된 보고만 한 번에 처리됩니다. 별개의 보고를 연속 행동 시간으로 합산하지 않습니다. 다른 교사가 이미 다른 결과를 저장했거나 기록이 철회됐다면 전체 묶음을 저장하지 않고 새로고침을 안내합니다.
6. 카메라 정지·동의 철회·패널 종료·로그아웃 때는 카메라가 꺼지는지, 사진 출석은 그대로 유지되는지도 확인하세요. 실시간 영상 전송 기능은 추가하지 않았습니다.
